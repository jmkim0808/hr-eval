# ADR-0013 실패는 기록하고, 하루 한 번 관리자에게 요약 메일

- **정해야 했던 것**: 실패를 어떻게 잡고 결정권자는 어디서 확인할지. 전산팀이 없다.
- **선택지**: ① 외부 오류 감시 서비스(Sentry 등) ② Cloudflare 로그만 ③ 우리 DB의 오류 기록 + 하루 한 번 요약 메일 + Cloudflare 로그
- **고른 것**: ③. 예상된 실패(잘못된 입력, 권한 없음, 잠김, 판본 충돌)는 화면에 용어집 말로 안내하고 기록하지 않는다. 예상 못 한 실패는 `error_logs`에 장소·요청 번호·짧은 메시지만 남긴다(**개인정보·점수·업적 글은 넣지 않는다**). 사용자 화면에는 "문제가 생겼습니다. 요청 번호 A1B2"만 보인다. 메일 발송 실패는 결과 발송·진행 현황 화면에 사람별로 보인다. 지난 24시간 동안 오류가 있으면 아침 8시에 관리자에게 건수와 요청 번호를 메일로 보낸다.
- **포기한 것**: 실시간 경보, 오류 묶음 분석. 120명 규모에 과하다.
- **다시 볼 때**: 하루 오류가 10건을 넘는 날이 생길 때 / 외부 판매를 검토할 때.
