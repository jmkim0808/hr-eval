# ADR-0021 평가 내용 암호화: 열쇠는 인사 관리자만

- **정해야 했던 것**: 서버·DB는 전산 담당자가 관리한다. 그래도 점수·업적 글·등급은 전산 담당자도 볼 수 없어야 한다(결정권자 요구).
- **선택지**: ① 별도 DB만 만들기 (DB 관리자는 여전히 다 볼 수 있음 — 효과 없음) ② 운영 통제만(접근 기록·서약) ③ 앱에서 암호화하고 열쇠는 인사 관리자만 ④ 외부 열쇠 관리 서비스(KMS/HSM) (비용·운영 부담)
- **고른 것**: ② + ③. 저장 전에 AES-256-GCM으로 암호화한다: 점수(본인·1차·2차), 업적·개선 글, 가점, 최종평가(점수·순위·등급·상위 %·조정 표시), 등급조정 이력(대상·등급·종류). 등급조정 작업 기록에는 누구를·어느 등급으로를 남기지 않는다. 데이터 열쇠는 **서버 메모리에만** 있고, DB에는 관리자마다 자기 비밀 문구(12자 이상, PBKDF2-SHA256 60만 회)로 잠근 "열쇠 칸"만 남는다. 서버가 다시 켜지면 잠긴 상태로 시작하고, 인사 관리자가 `/admin/vault`에서 비밀 문구를 넣어 연다(그 전에는 직원·대표이사는 안내 화면, 평가 진행 중이면 관리자에게 알림 메일). 연속 5번 틀리면 15분 쉼. 비밀 문구는 저장·기록하지 않는다.
- **남는 한계 (숨기지 않음)**: 이름·이메일·부서·직급·평가자 지정·제출 시각은 평문이다(진행 현황·독촉에 필요). 서버 관리자 권한으로 **열려 있는 서버의 메모리**를 들여다보거나 프로그램을 바꿔 치기하면 막을 수 없다 → 운영 통제(서버 접근 기록, 배포는 인사 확인 후, 서약)로 보완한다.
- **포기한 것**: 서버 재시작 뒤 자동 복구(사람이 열어야 함). 비밀 문구를 모두 잃으면 **복구할 수 없다** → 열쇠 칸을 2개 이상(담당자 + 봉인 보관용 예비) 두도록 화면에서 안내.
- **다시 볼 때**: 회사가 열쇠 관리 서비스를 도입할 때 / 평가 대상이 법인까지 넓어질 때.
