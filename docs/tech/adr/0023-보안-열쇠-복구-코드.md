# ADR-0023 보안 열쇠 복구 코드를 필수로 둔다

- 날짜: 2026-10-26
- 상태: 채택 (ADR-0021 보완)

## 배경
평가 내용은 관리자 비밀 문구로 잠근 열쇠로만 열린다(ADR-0021). 인사평가 담당 관리자가 1명이라, 비밀 문구를 잊거나 담당자가 갑자기 바뀌면 평가 내용을 아무도 복구할 수 없다. "예비 열쇠 칸을 만들어 두세요"라는 안내는 사람이 잊으면 그만이다.

## 결정
1. **복구 코드**: 열쇠가 열린 상태에서 시스템이 무작위 코드(5글자×6묶음, 150비트, 헷갈리는 글자 없음)를 만들어 **한 번만** 보여 준다. 그 코드로 같은 데이터 열쇠를 한 번 더 잠가 `key_slots`(kind=recovery)에 둔다. 코드 자체는 저장하지 않는다.
2. 관리자는 인쇄(또는 옮겨 적기)해 봉인·금고 보관하고, **종이를 보고 다시 입력해 맞아야 확정**된다 (옮겨 적기 실수 방지).
3. **확정된 복구 코드가 없으면 평가를 시작(안내 이메일 발송)할 수 없다.** 진행 중이면 진행 현황에 경고를 띄운다.
4. 잠긴 화면의 같은 입력 칸에 비밀 문구 대신 복구 코드를 넣으면 열린다. 그러면 "사용함"이 되어 다시 만들라는 안내가 나온다(새 비밀 문구 → 잊은 열쇠 칸 삭제 → 복구 코드 다시 만들기).
5. 복구 코드를 다시 만들어 확정하면 예전 코드는 지워진다. 복구 코드 칸은 일반 [지우기]로 지울 수 없다. 마지막 **비밀 문구** 열쇠 칸도 지울 수 없다.
6. 개발·시험 서버(메일 안 보냄 + 자동 열기)에서는 3번을 적용하지 않는다.

## 결과·한계
- 담당자가 바뀌면: 전산이 새 관리자 계정을 만들고(`seed:admins`), 새 담당자가 금고의 복구 코드로 연 뒤 자기 비밀 문구를 만든다.
- 복구 코드 종이를 가진 사람은 서버에 접근할 수 있으면 열쇠를 열 수 있다 → 봉인·금고 보관, 열람 기록, 쓰면 즉시 교체.
- 금고 종이까지 잃으면 여전히 복구할 수 없다 → 단계마다 백업 엑셀 보관은 계속한다.
