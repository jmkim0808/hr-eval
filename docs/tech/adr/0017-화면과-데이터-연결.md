# ADR-0017 화면은 서버에서 그때그때 읽고, 저장 후 다시 그린다

- **정해야 했던 것**: 화면이 데이터를 언제 가져오고 언제 새로 고칠지.
- **선택지**: ① 브라우저가 데이터를 받아 와 저장해 두는 방식(React Query 등) ② 서버가 화면을 그릴 때마다 DB에서 읽기 + 저장 동작 뒤 해당 화면 다시 그리기 ③ 실시간 연결(웹소켓)
- **고른 것**: ②. 로그인이 필요한 모든 화면은 저장해 두지 않고(캐시 없음) 매번 새로 그린다. 저장은 서버 동작으로 하고, 성공하면 그 화면을 다시 그린다(`revalidatePath`). 예외로 짧은 간격의 "새로 보기"를 둔 곳은 셋이다: ① 메일 발송 진행 숫자(3초), ② 대표이사 등급 결과(10초 — 조정이 바로 보여야 함), ③ 임시저장 표시(입력 1.5초 뒤). 실시간 연결은 쓰지 않는다.
- **포기한 것**: 화면 전환 시 순간 표시, 진짜 실시간. 120명 규모에서는 매번 읽어도 충분히 빠르고, 극대외비 데이터를 브라우저에 쌓아 두지 않는다.
- **다시 볼 때**: 화면 열림이 2초 이상 걸린다는 불만이 생길 때.
