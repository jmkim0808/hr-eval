# ADR-0018 개발용과 실제용 분리, 비밀값은 배포 환경에만

- **정해야 했던 것**: 개발하다가 실제 직원에게 메일이 나가거나 실제 평가 데이터를 건드리는 사고를 막는 방법.
- **선택지**: ① 하나로 운영 ② 개발용·실제용 두 벌 ③ 개발·검증·실제 세 벌
- **고른 것**: ②. Supabase 무료 플랜의 프로젝트 2개(개발용 `hr-eval-dev`, 실제용 `hr-eval-prod`, 둘 다 서울). Cloudflare Worker 2개(`hr-eval-dev`, `hr-eval`). 개발용은 **메일을 실제로 보내지 않고 기록만 남기는 방식**(`MAIL_MODE=log`)이 기본이고, 허용 목록에 있는 주소로만 보낼 수 있다. 실제 직원 데이터는 개발용에 넣지 않는다(가짜 명단 사용). 비밀값(DB 주소, SMTP 비밀번호, 해시용 비밀값, 예약 실행 비밀값)은 Cloudflare Worker 비밀값과 개인 PC의 `.dev.vars`(저장소에 올리지 않음)에만 둔다. 저장소에는 `.dev.vars.example`만 둔다. 실제용 배포는 `main` 브랜치에 합쳐질 때만 일어난다.
- **포기한 것**: 별도의 검증 환경. 내부 공유 단계에서는 개발용이 그 역할을 겸한다.
- **다시 볼 때**: 회사 서버 이전 시 / 개발자가 2명 이상이 될 때.
