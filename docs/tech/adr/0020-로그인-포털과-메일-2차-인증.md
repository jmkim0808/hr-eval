# ADR-0020 로그인: 포털 로그인(1차) + 회사 메일 인증번호(2차)

- **정해야 했던 것**: 포털 사양은 포털 로그인 토큰(JWT)을 쓰라고 한다. 그러나 극대외비라 포털 비밀번호 하나만으로는 부족하다는 결정권자 의견.
- **선택지**: ① 포털 로그인만 ② 포털 로그인 + 메일 인증번호 ③ 포털에는 링크만 두고 별도 로그인(ADR-0005 그대로)
- **고른 것**: ②. 1차: 화면이 브라우저 저장소의 `ax_access_token`을 서버에 넘기고, 서버가 요청마다 HS256 서명(`JWT_SECRET_KEY`)·만료(30초 여유)를 확인한다. `alg`가 HS256이 아니면 거부, `must_change_password`면 거부. 토큰의 `sub`(사번)로 사람을 찾는다(관리자·대표이사 계정 → 올해 명단 순, 접근 차단된 사람은 "등록되지 않은 사번"). 2차: 그 사람의 **등록된 회사 메일**로 6자리 인증번호(ADR-0005 규칙 그대로, 메일에는 링크 없음). 이메일을 직접 입력하는 칸은 없앴다. 세션 쿠키는 `path=/hr-eval`로 포털의 다른 앱에 가지 않는다. 같은 PC에서 포털 사용자가 바뀌면(토큰의 사번 ≠ 세션의 사번) 화면 이동·창 전환 때 바로 로그아웃한다. 명단·관리자 등록에 **사번**이 필수가 되었다.
- **포기한 것**: 포털 한 번 로그인으로 바로 들어가는 편의. 평가 기간에 하루 한 번 정도 메일 인증이 더 든다(세션 30분/최대 12시간).
- **다시 볼 때**: 포털이 OTP·기기 인증 같은 2단계 인증을 직접 제공할 때 / 포털 사번과 인사 사번이 다를 때(전산 확인 필요).
