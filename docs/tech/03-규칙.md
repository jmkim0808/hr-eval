# 3. 규칙 — 코드를 쓸 때마다 지키는 약속

> 이유는 `adr/`에 있다. 여기에는 약속만 적는다. 디자인 약속은 `docs/ui/01-디자인-규칙.md`와 `.cursor/rules/design-system.mdc`에 있다.

## 기술 묶음 (바꾸려면 ADR을 새로 쓴다)

- Next.js App Router + TypeScript(strict) + React Server Components
- 배포: Cloudflare Workers (`@opennextjs/cloudflare`). Node.js(`output: "standalone"`) 빌드도 항상 통과해야 한다.
- DB: PostgreSQL (지금은 Supabase), Drizzle ORM + postgres.js
- 입력 검사: zod / 엑셀: ExcelJS / 아이콘: lucide-react / 테스트: Vitest
- **새 라이브러리를 더하기 전에** 위 묶음으로 안 되는지 먼저 본다. 더하면 이유를 한 줄로 PR에 적는다.

## 이식성 (회사 서버로 옮길 수 있게)

1. Supabase 전용 기능을 쓰지 않는다. `@supabase/*` 패키지, 데이터 API, RLS 정책, Auth, Storage, Realtime, Edge Functions, pg_cron이 모두 해당한다. DB는 `DATABASE_URL` 하나로만 접속한다.
2. Cloudflare 전용 코드(`getCloudflareContext`, Cron 처리기, `ctx.waitUntil`, TCP 소켓 메일)는 `src/platform/` 안에만 둔다. 나머지 코드는 `platform`이 내보내는 함수만 부른다.
3. DB 구조는 `drizzle-kit generate`로 만든 마이그레이션 SQL로만 바꾼다. 대시보드에서 손으로 고치지 않는다. 마이그레이션 SQL은 사람이 읽고 합친다.

## 권한과 데이터 접근

4. DB를 읽고 쓰는 코드는 `src/server/repo/`에만 있다. 화면 코드와 서버 동작에서는 DB를 직접 부르지 않는다.
5. `repo`의 모든 함수는 첫 인자로 `actor`(누가 묻는지)를 받고, `src/server/authz/`의 허용 표를 통과한 칸만 꺼낸다. **허용되지 않은 칸은 SELECT 하지 않는다** (화면에서 숨기는 것으로 대신하지 않는다).
6. 잠김·쓰기 가능 여부는 `review_cycles.status`로만 판단한다. 따로 "잠김" 칸을 만들지 않는다.
7. 서버 동작(Server Action)·주소 처리기(Route Handler)의 첫 줄은 항상 `requireActor()`다. 예외는 이메일 인증 화면과 예약 실행 주소(비밀값 확인) 두 곳뿐이다.
8. 권한 허용 표(`docs/tech/02-데이터-구조.md` 2-3)를 바꾸면 같은 PR에서 `authz` 테스트도 바꾼다.

## 입력과 출력

9. 사용자 입력은 모두 zod로 검사한다. 점수는 정수 1~10. 업적 글은 칸당 4,000자. 이름은 50자, 이메일은 254자까지.
10. 엑셀은 1MB 이하 `.xlsx`, 1,000줄까지만 받는다. 제목 줄이 템플릿과 정확히 같아야 한다. 원본 파일은 저장하지 않는다.
11. 내보내는 엑셀에서 `= + - @`로 시작하는 글자는 앞에 `'`를 붙인다.
12. 화면 글은 `docs/domain/02-공통-용어집.md`의 말을 그대로 쓴다. 날짜와 시각은 `Asia/Seoul` 기준으로 저장(timestamptz)·표시한다.
13. 점수 계산은 `src/domain/grading/`의 순수 함수로만 한다. 소수는 `numeric`(DB)과 정수 연산(코드)으로 다루고, JS 실수 계산을 그대로 저장하지 않는다.

## 실패 처리

14. 예상된 실패(입력 오류·권한 없음·잠김·판본 충돌·한도 초과)는 `{ ok: false, code, message }`로 돌려주고 화면에 용어집 말로 보여 준다. `throw`하지 않는다.
15. 예상 못 한 실패는 `throw`하고, 가장 바깥에서 `error_logs`에 장소·요청 번호·짧은 메시지만 남긴다. 화면에는 요청 번호만 보인다.
16. **기록(로그)에 개인정보를 넣지 않는다.** 이름, 이메일, 점수, 업적 글, 인증번호가 모두 해당한다. 사람은 id로만 적는다.
17. 판본 번호(`version`)가 있는 표는 `WHERE version = :기존값`으로 저장하고, 0줄이 바뀌면 판본 충돌로 돌려준다.

## 메일

18. 메일은 `MailSender`로만 보낸다. 인증번호를 뺀 모든 메일은 `email_outbox`에 쌓는다.
19. 메일 본문에 점수·등급·업적 글·등급조정 여부를 넣지 않는다. 결과는 링크로만 안내한다.
20. 개발용 환경은 `MAIL_MODE=log`가 기본값이다. 실제 발송은 허용 목록에 있는 주소로만 한다.

## 비밀값과 환경

21. 비밀값은 코드와 저장소에 쓰지 않는다. Cloudflare Worker 비밀값과 개인 PC의 `.dev.vars`에만 둔다. 브라우저로 가는 환경 변수(`NEXT_PUBLIC_*`)에는 비밀값을 넣지 않는다.
22. 실제 직원 데이터는 개발용 DB에 넣지 않는다.

## 테스트와 합치기

23. `domain/grading`과 `server/authz`는 테스트 없이 합치지 않는다. 도메인 문서의 예시(동점·밀려남·반올림)를 테스트로 둔다.
24. 합치기 전에 `typecheck`, `lint`, `test`, Workers 빌드, Node 빌드를 통과해야 한다.
