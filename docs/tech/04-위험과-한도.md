# 4. 위험과 한도표

> 확인일 2026-10-01. 요금·한도는 각 회사 정책에 따라 바뀐다. 표에 **(확인)** 이라고 적은 것은 공식 문서나 검색으로 확인했고, **(추정)** 이라고 적은 것은 우리 사용량을 계산하거나 짐작한 값이다.
> 환율은 1달러 = 1,400원으로 계산했다 (추정).

## 4-1. 돈이 드는 곳

| 항목 | 요금 | 언제 | 1년 예상 |
|---|---|---|---|
| Cloudflare Workers 유료 | 월 5달러 (확인) | 개발 시작부터. 쓰지 않는 달은 해지 가능 | 최대 60달러 (약 8.4만 원) |
| Supabase Pro | 월 25달러 (확인) | **평가 기간(10~12월)만 — 승인 대기** | 75달러 (약 10.5만 원) |
| 다우오피스 메일 발송 | 0원 (기존 계약) | — | 0 |
| 도메인 | 0원 (`*.workers.dev` 또는 회사 도메인 하위 주소) | — | 0 |
| **합계** | | | **약 135달러 (약 19만 원)**. Supabase를 무료로만 쓰면 약 60달러 (약 8.4만 원) |

## 4-2. 무료·유료 한도의 경계

| 서비스 | 한도 | 우리 사용량 | 넘으면 생기는 일 | 지금 할 대응 | 나중에 할 대응 |
|---|---|---|---|---|---|
| Cloudflare Workers 유료 | 월 1,000만 요청, CPU 3,000만 ms 포함, 프로그램 크기 10MB (확인) | 11월 피크 월 5만 요청 이하 (추정) | 초과분 소액 과금 | Cloudflare 결제 알림 설정 | 없음 |
| Cloudflare 무료로 내릴 경우 | 하루 10만 요청, **요청당 CPU 10ms, 크기 3MB** (확인) | — | 화면이 가끔 오류로 뜸 | 쓰지 않음 (ADR-0002) | 쉬는 달에 해지하면 그동안 서비스 접속 불가 → 쉬는 기간 열람이 필요한지 판단 |
| Supabase 무료 | DB 500MB, 프로젝트 2개, **7일 미사용 시 멈춤, 자동 백업 없음** (확인) | 1년 수 MB (추정) | 멈춤: 접속 불가, 대시보드에서 수동 재개 (1년 안에는 복원 가능 — 확인) | 하루 한 번 예약 실행이 DB 조회 (멈춤 방지) | 회사 서버 이전 시 해소 |
| Supabase Pro | 일일 백업 7일치, 멈춤 없음 (확인) | — | Spend Cap을 켜 두면 초과 과금 대신 제한만 걸림 | Pro 전환 시 Spend Cap 켜기 | 마감 후 무료로 내리기 (일정표에 등록) |
| 다우오피스 SMTP | **계정당 하루 발송 한도 — 확인 필요** | 첫날 안내 120 + 인증번호 약 150 = 하루 300통 이하 (추정) | 그날 남은 메일 발송 실패 → 다음 날 이어서 보냄 | 발송 전용 계정 만들 때 한도와 외부 SMTP 접속 허용 여부를 다우오피스에 확인 | 막히면 Resend 유료(월 20달러)로 바꿈 — `MailSender`만 교체 |

## 4-3. 미리 짚은 위험

| 위험 | 실제로 문제가 되는 때 | 지금 할 일 | 나중에 할 일 |
|---|---|---|---|
| **남의 데이터가 보임** (팀장이 2차 점수, 직원이 남의 결과) | 권한 코드를 빠뜨린 화면을 추가할 때 | 권한 검사 한 곳 + 허용되지 않은 칸은 아예 꺼내지 않기 + 허용 표 전체 자동 테스트 + DB 데이터 API 끄기 (ADR-0003·0004) | 회사 서버 이전 시 접속 계정 권한 다시 점검 |
| **인증번호 메일 폭주** (누군가 이메일을 계속 넣음) | 공개 주소가 알려졌을 때 | 이메일당 1시간 5번, 접속 주소당 30번 제한. 명단에 없는 이메일은 실제로 보내지 않음 | 계속되면 Cloudflare의 무료 봇 차단(Turnstile) 추가 |
| **11월 첫날 몰림** | 안내 메일 120통 직후 | 메일은 목록에 쌓아 나눠 보냄. 인증번호는 즉시 발송 | — |
| **처리 시간 초과** | 엑셀 1,000줄 이상, 메일을 한 번에 보낼 때 | 엑셀 1,000줄 제한, 메일은 30통씩 나눠 보냄 | 3법인 통합 등으로 커지면 다시 봄 |
| **이상한 입력** (거대한 파일, 엑셀 수식, 스크립트 글) | 실수 또는 악의 | 1MB·.xlsx·제목 줄 검사, 내보낼 때 수식 무력화, 화면은 글자를 그대로 표시(스크립트 실행 안 됨), 업적 글 4,000자 | — |
| **여러 창·여러 관리자 동시 수정** | 두 창에서 같은 평가지, 관리자 둘이 동시에 등급조정 | 판본 번호로 나중 저장을 막고 "새로 불러오기" 안내 (ADR-0012) | — |
| **평가자 점수가 빈 채 잠김** | 미제출 평가자를 두고 단계를 넘길 때 | **업무 규칙 결정 대기 (ADR-0016)** | — |
| **반올림 합계 불일치** | 그룹 인원이 20명 미만일 때 흔함 | **업무 규칙 결정 대기 (ADR-0015)** | — |
| **데이터가 사라짐** | 잘못된 조작, 서비스 사고 | 평가 기간 Supabase Pro 일일 백업(승인 대기), 마감 시 전체 기록 엑셀 백업, 등급조정은 이력 보존 | 회사 서버 이전 시 회사 백업 정책 적용 |
| **Supabase가 7일 미사용으로 멈춤** | 12월~10월 쉬는 기간 | 하루 한 번 깨우기 조회 | 정책상 막히면 마감 후 백업만 두고 멈춤 허용 (평가 전 재개) |
| **SMTP 비밀번호 유출** | 비밀값 관리 실수 | 발송 전용 계정, 비밀값은 배포 환경에만, 개발용은 실제 발송 안 함 | 비밀번호 변경 시 Cloudflare 비밀값만 바꾸면 됨 |
| **로그·오류 기록으로 개인정보 유출** | 디버깅용 기록을 남길 때 | 기록에 개인정보 금지 (규칙 16) | — |
| **개인정보 처리 위탁 고지 누락** | 직원 개인정보를 외부 업체(Cloudflare·Supabase)가 처리 | **[결정권자 할 일]** 사내 개인정보 처리방침에 수탁자(Cloudflare, Supabase)와 처리 목적 기재·고지 (서버 위치: Supabase 서울. Cloudflare는 전 세계 지점에서 처리) | 회사 서버로 옮기면 위탁 고지 정리 |
| **남에게 보여주거나 팔 때** | 다른 회사가 쓰려 할 때 | 해당 없음 — 지금 구조는 **한 회사 전용**(회사 구분 칸 없음, 파워넷 양식·규칙이 코드에 들어 있음) | 판매를 검토하면 회사 구분, 양식 설정 화면, 로그인 방식(SSO)을 새로 설계해야 함 (약 4~6주 추가 — 추정) |

## 4-4. 미뤄 둔 것

| 미룬 것 | 언제 다시 꺼내나 |
|---|---|
| 보관 기한 자동 점검·삭제 기능 | **2029년 평가 시작 전** (2026년 마감분의 기한이 처음 돌아옴) |
| 외부 서버 vs 회사 서버 결정 | 내부 공유 후 |
| 봇 차단(Turnstile) | 인증번호 요청이 비정상적으로 많아질 때 |
| 다우오피스 계정 연동 로그인 | 그룹웨어 로그인 요구가 나올 때 |
| 외부 오류 감시 서비스 | 하루 오류가 10건을 넘는 날이 생길 때 |
| 3법인 통합 | 범위가 바뀔 때 (도메인 문서의 "해결하지 않을 것") |
