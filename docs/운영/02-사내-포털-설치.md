# 사내 포털 설치 — 인사평가 (`/hr-eval`)

전산 담당자와 인사 담당자가 같이 본다. ★는 전산 담당자에게 받아야 하는 값.

## 1. 전산 담당자에게 받을 것 (확인 필요)

| # | 받을 것 | 왜 필요한가 |
|---|---|---|
| 1 | ★ 포털 토큰의 `sub`가 **인사 사번과 같은지** | 포털 로그인한 사람을 사번으로 찾는다. 다르면 대응표가 필요 |
| 2 | ★ PostgreSQL 전용 DB·계정(`DATABASE_URL`)과 **백업 주기** | 데이터는 모두 DB에 있다. 앱은 파일을 저장하지 않는다 |
| 3 | ★ 서버에서 **다우오피스 SMTP**로 메일을 보낼 수 있는지 (호스트·포트·계정) | 2차 인증번호·안내·독촉 메일 |
| 4 | ★ 앱 이름·배정 포트·경로(기본 `/hr-eval`)·포털 주소 | `ax-app.yaml`, `APP_URL`, `BASE_PATH` |

## 2. 설치 순서

1. 포털 환경 값에 `ax-app.yaml`의 env 목록을 채운다 (`MAIL_MODE=smtp`, `HR_DEV_PASSPHRASE`는 넣지 않음).
2. `npm ci && npm run build`
3. `npm run db:migrate`
4. `npm run seed:admins -- "이름:이메일:사번"` (인사 관리자 2명 권장), `npm run seed:ceo -- "이름:이메일:사번"`
4-1. **메일 사전 시험** (2026-10-21): 서버에서 `node scripts/mail-test.mjs` → 환경 값의 SMTP로 시험 메일 1통을 보내고, 안 되면 이유(계정·포트·방화벽·TLS)를 알려 준다. 인사 담당자 PC에서는 `메일-발송-시험.bat`으로 같은 시험을 할 수 있다(값은 그때 입력, 저장 안 함).
5. `node scripts/start.mjs --port <배정 포트>` → `/hr-eval/health` 가 `{"status":"ok"}`
6. **인사 관리자**가 포털에서 인사평가를 열고 2차 인증 → `보안 열쇠` 화면에서 비밀 문구(12자 이상)로 열쇠를 만든다 → 곧바로 두 번째 관리자(또는 봉인 보관용 예비) 열쇠 칸을 추가한다.

## 3. 서버를 다시 켤 때마다 (중요)

서버가 다시 켜지면 보안 열쇠가 **잠긴 채** 시작한다. 평가가 진행 중이면 관리자에게 "보안 열쇠를 열어야 합니다" 메일이 간다. 관리자가 `보안 열쇠` 화면에서 비밀 문구를 넣기 전까지 직원·대표이사는 "잠시 이용할 수 없습니다" 화면만 본다.
→ 전산 담당자는 **서버 재시작·패치 일정을 인사 담당자에게 미리 알려 준다.**

## 4. 7. 마지막 점검 (포털 사양서 제출용)

| 점검 항목 | 결과 | 쉬운 설명 |
|---|---|---|
| 코드에 비밀번호·키가 없다 (`.env.example`만) | 예 | 비밀값은 포털 환경 값에만 넣는다. 저장소 검사에서 실제 값 없음 |
| `.env`·`.pem`·`.key`가 `.gitignore`에 있다 | 예 | `.env*`(예시 파일 제외), `*.pem`, `*.key`, `*.pfx`, `*.crt` |
| 실제 개인정보가 저장소·개발 DB에 없다 | 예 | 시험은 가짜 명단(`@powernet.test`)만 쓴다 |
| 외부 AI를 직접 부르지 않는다 | 예 | AI 기능 없음 (ADR-0009) |
| `eval`·`exec` 없음, SQL은 매개변수 방식 | 예 | 코드 검사로 확인. DB 접근은 Drizzle ORM(매개변수 자동) |
| `127.0.0.1` + 포트를 코드에 박아 두지 않았다 | 예 | 포트는 `--port` 또는 `PORT`로 받는다. 받는 주소는 사양대로 127.0.0.1 |
| 저장소 맨 위에 `ax-app.yaml` | 예 | ★ 표시(포트·이름·경로·DB·SMTP)는 전산 값 받은 뒤 채움 |
| 데이터 폴더는 `AX_DATA_DIR` | 해당 없음 | 파일을 저장하지 않는다 (모두 PostgreSQL) |
| 모든 주소가 `base_path` 아래, 포트 하나 | 예 | `/hr-eval` 아래 화면·API·health 모두 |
| 화면 끼우기 막지 않음 (`DENY` 없음) | 예 | `X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'` |
| `/health` | 예 | `/hr-eval/health` → 200 `{"status":"ok"}` |
| 포털 JWT 로그인 (`ax_access_token`, HS256, `must_change_password` 거부) | 예 + 2차 인증 | 포털 로그인(1차) 뒤 회사 메일 인증번호(2차)를 더 받는다 (ADR-0020) |
| 내려받기 DLP 기록 (`/api/dlp/exports`) | 예 | 엑셀 4종(최종결과·백업·가점 템플릿·명단 템플릿) 내려받을 때마다 기록 |
| 의존성 버전 고정, README, 시험 | 예 | `package.json` 정확한 버전 + `package-lock.json`, 단위 시험 58개, 화면 시험 21묶음 |
| 제출 | 대기 | ★ 값 받은 뒤 `v1.0.0` 태그로 제출 |

## 5. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 보안 열쇠 비밀 문구를 모두 잃음 | 평가 내용 **복구 불가** | 열쇠 칸 2개 이상(담당자 + 봉인 보관 예비), 단계마다 엑셀 백업 |
| 평가 기간 중 서버 재시작 | 관리자가 열 때까지 전원 이용 중단 | 재시작 일정 사전 공유, 자동 알림 메일, 관리자 2명 |
| 포털 사번 ≠ 인사 사번 | 로그인 불가 | 설치 전 1번 항목 확인, 다르면 명단 사번을 포털 기준으로 |
| SMTP 차단 | 인증번호가 안 와 아무도 못 들어옴 | 설치 전 3번 항목 시험 발송 |
| 서버 관리자가 실행 중 메모리·프로그램을 조작 | 암호화로도 막을 수 없음 | 서버 접근 기록, 배포는 인사 확인 후, 비밀유지 서약 (ADR-0021 한계) |
| exceljs가 쓰는 uuid 라이브러리 보안 알림(중간) | 실제 영향 낮음(쓰지 않는 기능) | 엑셀 라이브러리 새 판이 나오면 올림 |
